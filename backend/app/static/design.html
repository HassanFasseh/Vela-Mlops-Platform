Vela — Design System Phase 1

A calm, dense, near-black developer console — hairline borders carry the structure, type is small and sharp with obvious hierarchy, and color appears only to report status (deploys, health, drift, errors), never for decoration. Dark is the designed-for theme; light is provisional.

Color

Color carries meaning, never decoration
The interface is neutral by default. A hue appears only when a value has crossed a threshold or an element reports a real state — a failed deploy, a drifting feature, an endpoint that is down. A meter at 38%, a count of 24 deployed models, a request rate: all neutral. Blue is navigational only (links, focus, active nav) and never fills a button.

Forms

Labels sit above the control in sentence case, spacing is generous, and inputs are a light 1px hairline that firms on hover and sharpens to an accent ring on focus — no filled or boxy fields. Validation is inline: the border carries the state, a short message below spells it out. A clean form shows no color at all.

Cards & panels

A plain card is a surface plus a 1px border — no left accent bar. Selection (.is-selected) reads as a uniform near-white border on all four sides — monochrome, matching the primary button, never blue, and never a single-side bar. The border width is unchanged, so selecting a card never shifts its contents.

Meters

Fill is neutral gray until the value crosses a threshold. There is no "healthy" green — a normal reading simply isn't colored. Only .is-warning and .is-error paint the bar, and the read-out follows the bar (add .is-warning / .is-error to .meter-label).

Layout shell

Sidebar (one shade off the content area, 2px accent indicator on the active item), a 48px top bar with breadcrumbs and a command trigger, then the canonical page header + toolbar + table. Below 900px the sidebar becomes an off-canvas drawer with a scrim; below 560px the top bar tightens, the toolbar and page actions stack, and tables scroll inside their container.
